What’s new

  • Restore exact Pi sessions after a Mac restart. Agent Visor can reopen the interactive Pi sessions it was tracking in Ghostty, using each durable session file rather than guessing from a project name or recent directory. Same-boot relaunches and already-running exact owners are excluded to prevent duplicates.
  • First-class Zed-hosted agents. Pi, Codex, and Claude threads hosted through Zed now keep Zed’s thread title and owner identity. Opening a session activates the correct Zed channel and worktree, then uses a verified best-effort sidebar reveal when the title is unique. Zed-hosted Chat remains read-only.

Improvements and fixes

  • Recovered Pi sessions that stayed on Working after a best-effort completion event was dropped. The Pi runtime heartbeat now supplies exact idle evidence, and manual compaction reports its closing boundary.
  • Detected unresolved Codex Desktop questions and elevated-permission requests directly from observed rollout data, so they appear as Needs attention without requiring a terminal hook.
  • Backfilled a Pi runtime’s controlling TTY when its lifecycle event omitted one, preserving exact terminal navigation and input.
  • Prevented stale startup-transcript discovery from publishing duplicate or ghost Pi sessions after /new, /resume, or /fork.
  • Fixed double-tapping Shift leaving the Sessions browser visible but covered by another application.
  • Reduced status-pulse work on high-refresh displays and stabilized both menu-bar ownership boundaries to prevent pill flapping during activation and display changes.
  • Made Claude usage more compact and explicit with a fixed CC $remaining glance while retaining the full used/limit breakdown in the popover.

Pi reboot restoration is intentionally limited to exact, persisted, interactive Ghostty sessions observed by Agent Visor. It does not replay prompts, restore unsupported hosts, or create substitute sessions when an exact session file is unavailable.
